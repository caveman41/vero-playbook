# Деплой сторінки — покрокова інструкція

Як залити готову сторінку на живий сайт VeroCleaning. Порядок дій має значення — кожен крок захищає від конкретної помилки, яка вже траплялась на цьому проєкті.

**Читати перед цим:** `site-technical-docs.md` (як влаштований сайт)

---

## Перед стартом

- [ ] Макет пройшов чек-ліст приймання (дизайн-система, контраст, структура)
- [ ] Контент написаний, ціни звірені з `vero-facts.json`
- [ ] SEO-частина готова: title, description, OG, schema
- [ ] Є доступ до WP-адмінки й WPCode

---

## Крок 1 · Снапшот перед будь-якою зміною

🔴 **У WPCode немає історії версій.** Якщо перезаписати сніпет і щось зламається — відкату не існує.

1. Відкрий кожен сніпет, який будеш змінювати
2. Скопіюй увесь вміст у локальний файл: `_backup/[дата]/[назва-сніпета].[css|js|html]`
3. Тільки після цього редагуй

Те саме для пост-контенту сторінки: експортувати перед заміною.

---

## Крок 2 · Винести зображення

У макеті зображення зазвичай вшиті в код як base64. На макеті головної це було **80% ваги файлу** — 249 КБ із 311 КБ.

1. Витягнути кожне зображення з base64 у файл
2. Залити через **Media Library**
3. Замінити `src="data:image/jpeg;base64,..."` на URL із медіатеки
4. Перевірити, що `alt` збережені й описові

⚠ Великий base64 підвішує інструменти розробки. Це не тільки про швидкість сайту.

---

## Крок 3 · Розділити код на три частини

Макет приходить одним HTML-файлом. На сайті він живе окремо:

| Частина | Куди |
|---|---|
| HTML-розмітка | Gutenberg-блок сторінки (Custom HTML) |
| CSS | WPCode-сніпет, тип CSS |
| JS | WPCode-сніпет, тип JS |

Зі сторінки прибрати: `<html>`, `<head>`, `<body>`, `<style>`, `<script>` — лишається тільки вміст `<body>`.

---

## Крок 4 · Створити сніпети

### CSS-сніпет

| Налаштування | Значення |
|---|---|
| Тип | CSS Snippet |
| Розміщення | Site Wide Header |
| Пріоритет | **50** |
| Умова | див. нижче |

🔴 **Пріоритет 50, а не 10.** `Vero_Styles` стоїть на 10 і вантажиться раніше. Якщо поставити новий сніпет теж на 10 або нижче — базові стилі перекриють сторінкові, а не навпаки.

### JS-сніпет

| Налаштування | Значення |
|---|---|
| Тип | JS Snippet |
| Розміщення | Site Wide Footer |
| Пріоритет | 50 |
| Умова | та сама |

Якщо JS залежить від даних із іншого сніпета (як `VC2_JS` від `VC2_Icons_Flat`) — залежність отримує **нижчий** пріоритет, щоб завантажитись раніше.

### Умова показу

| Сторінка | Умова |
|---|---|
| Головна | **Front Page** — не «URL contains» |
| Решта | Page URL contains `[слаг]` |

🔴 Головна живе на кореневому URL. Правило «URL contains» там не спрацює.

⚠ Перед використанням «URL contains» перевір, скільки адрес на сайті містять цей рядок. Для `/book` перевіряли: рівно дві (`/book/` і `/book-v2/`), витоку немає.

---

## Крок 5 · Неймспейс для JS

Якщо на сторінці є калькулятор або будь-яка логіка — **власний префікс функцій**.

Реальний випадок із проєкту: `Vero_Scripts` вантажиться глобально через `wp_footer` і визначає `veroState`, `veroStep`, `veroPickHome`. Це звичайні глобальні функції, не модуль. Калькулятор Deep Cleaning, який використав би ті самі імена, був би перезаписаний — і рахував би Deep як Regular.

Тому там префікс `veroDC*`, у калькуляторі `/book` — `vc2*`.

---

## Крок 6 · Залити й перевірити ВЖИВУ

🔴 **Gutenberg-деплой часто проходить частково:** структура оновлюється, текст — ні.

Після заливки обов'язково відкрити сторінку в браузері й перевірити:

- [ ] Текст справді змінився, не тільки розмітка
- [ ] Консоль браузера — нуль помилок
- [ ] Мобільна ширина 390 px — немає горизонтального скролу
- [ ] Десктоп 1440 px
- [ ] Хедер, футер, меню на місці
- [ ] Посилання ведуть куди треба
- [ ] Калькулятор рахує правильно (якщо є)

**Не вірити власному звіту про успіх без перевірки.** Це правило записане в інструкціях проєкту після реального інциденту.

- [ ] Alt-тексти описові

## Чого не робити

| Дія | Наслідок |
|---|---|
| Вимкнути `Calculator_CSS` (3818) або `Calculator_JS` (3817) | Зламається `/book` — вони тримають правила приховування рідної розмітки Fluent Forms |
| Видалити форму 14 | Зникне єдиний бекап 5-крокового калькулятора |
| Редагувати `/book` через пост-контент | Код форми там не лежить як текст. Тільки через Fluent Forms в адмінці |
| Змінювати живу БД без підтвердження власника | — |
| Покладатись на Kadence-класи | Сайт відходить від Kadence |
| Вбудовувати base64-зображення | Вага сторінки + підвисання інструментів |
