**Стан на:** вересень 2026
**Верифіковано:** читанням реального коду з файлів проєкту, не з пам'яті

## 4. Калькулятор `/book` — як працює

### Формула

```
core   = (homeBase + rooms + basement) × multiplier
rooms  = bed×30 + bath×40 + den×20 + halfBath×20
basement (якщо увімкнено) = 60 + bBed×30 + bBath×40 + bHalf×20
extras = appliances + hourly + carpet + sofa + homecare + steam + mattress   ← НЕ множаться
total  = core + extras − promo
recurring = total × 0.85
```

🔴 **Бейсмент усередині множника.** Було `base×mult + basement`, стало `(base+basement)×mult`. Виправлено 2026-08-15.

### Бази та множники

| Тип житла | База | | Тип прибирання | Множник |
|---|---|---|---|---|
| Condo / Apt | $80 | | Regular | ×1.0 |
| Townhouse | $100 | | Deep | ×1.5 |
| House | $110 | | Move-In/Out | ×1.8 |
| | | | Post-Renovation | ×2.2 |

Повний прайс extras — у `vero-facts.json §step_5_extras`.

### Структура коду

**`VC2_JS` (4117)** — одна IIFE, усі функції з префіксом `vc2`:

| Функція | Призначення |
|---|---|
| `vc2Calc()` | Головний розрахунок |
| `vc2RoomsCharge()` · `vc2BasementCharge()` · `vc2ExtrasCharge()` | Складові суми |
| `vc2Go(n)` | Перехід між 6 кроками |
| `vc2ReadParams()` | **Хендоф із головної** — читає GET-параметри |
| `vc2Submit()` | Надсилання у Fluent Forms |
| `vc2Bind()` · `vc2Init()` | Ініціалізація й події |

**Ключові id у розмітці:** `vc2-app` (корінь), `vc2-price-now`, `vc2-next`, `vc2-back`, `vc2-chip`, `vc2-postal`, `vc2-phone`, `vc2-cal-strip`. Повний перелік — у `book-v2_vc2-form.html`.

### 🔴 Хендоф із головної — контракт GET-параметрів

Це те, що з'єднує геро-калькулятор головної з `/book`. Функція `vc2ReadParams()` читає:

| Параметр | Значення | Приклад |
|---|---|---|
| `service` | тип прибирання | `regular` · `deep` · `moveinout` · `postreno` |
| `home` | тип житла | `condo` · `townhouse` · `house` (також приймає `apartment`, `apt` → condo) |
| `beds` | кількість спалень | `2` |
| `baths` | кількість ванних | `1` |
| `zip` | поштовий код | `M5V` (обрізається до 3 символів) |
| `phone` | телефон | форматується автоматично |

**Якщо передано `home` або `service` — калькулятор стартує одразу з кроку 2**, пропускаючи вибір типу.

Приклад: `/book?service=deep&home=condo&beds=1&baths=1`

⚠ Значення `moveinout` — **не** `moveout`. Помилка в одну літеру мовчки проігнорується.

### Сабміт

`vc2Submit()` заповнює дев'ять прихованих полів Fluent Forms і натискає рідну кнопку сабміту:

`total_price` · `clean_summary` · `promo_code` · `booking_date` · `booking_slot` · `client_name` · `client_email` · `client_phone` · `client_address`

🔴 **Не протестовано вживу** — потрібен дозвіл власника, бо створить запис в Entries. Email Notifications форми 9 у стані Disabled.

### Чого немає

- **Stripe не активований.** Платіжний блок із макета не реалізований
- **Таймер «слот тримається 10:00»** — прибраний, це вигаданий дефіцит
- Стара `vcOnSubmit` била в неактивований Stripe-ендпоінт і взагалі не зверталась до Fluent Forms — замінена

## 5. Скрипти сайту (`Vero — Scripts`)

Глобальний сніпет, працює на всіх сторінках. Функції з префіксом `vero`:

| Група | Функції |
|---|---|
| Міні-калькулятор героя | `veroRecalcMini` · `veroPickHome` · `veroStep` · `veroBasement` · `veroContinue` |
| Book in 60 seconds | `veroB60Step1Submit` · `veroB60Back` · `veroB60Submit` |
| Commercial quote | `veroPickQuoteProp` · `veroQuoteSubmit` · `veroScrollToQuote` |
| Інтерфейс | `veroSvcTab` (таби послуг) · `veroToggleFaq` · меню `veroNavOpen/Close` |
| Before/After | слайдер порівняння |

⚠ **Формула в `veroRecalcMini` позначена як чернетка** — коментар у коді каже «синхронізувати з реальним прайсом /book при активації Stripe». Тобто міні-калькулятор головної може розходитись із `/book`.

### 🔴 Конфлікт неймспейсів — реальна пастка

`Vero_DeepCleaning_Calc.js` використовує префікс `veroDC*`, **не** `veroState/veroStep/veroPickHome`. Причина зафіксована прямо в коді: ці імена вже зайняті глобальним `Vero_Scripts`, який вантажиться на кожній сторінці через `wp_footer`. Оскільки це звичайні глобальні функції, а не модуль, той скрипт, що завантажиться останнім, перезапише інший — і калькулятор рахуватиме Deep Clean як Regular.

**Правило:** будь-який новий калькулятор на окремій сторінці отримує власний префікс.

## 6. Пастки деплою

| Пастка | Наслідок |
|---|---|
| Немає історії версій у WPCode | **Снапшот сніпета перед кожним перезаписом.** Відкату немає |
| CSS головної — пріоритет 50, `Vero_Styles` — 10 | Менший пріоритет вантажиться раніше. Порушиш порядок — стилі перекриються не в той бік |
| Умова показу головної — **Front Page**, не «URL contains» | Головна на кореневому URL, правило за URL не спрацює |
| `backdrop-filter` + `position:sticky` | Ламається будь-яким `overflow:hidden` у предків |
| Gutenberg-деплой проходить частково | Структура оновлюється, текст — ні. **Перевіряти вживу після кожного деплою**, не вірити звіту про успіх |
| Великий base64 підвішує інструменти | Зображення — через Media Library, не в код |
| Модель у Cowork фіксується після першого повідомлення | Обирати усвідомлено на старті чату |

### Безпека

- Бекап файлу перед редагуванням, у `_backup/[дата]/`, нічого не видаляти
- Ніколи не змінювати живу БД без явного підтвердження власника
- Перед незворотною дією — питати підтвердження
