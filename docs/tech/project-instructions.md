# VeroCleaning.ca — Інструкції для роботи над проєктом

## Що це за проєкт
Сайт для клінінгової компанії VeroCleaning.ca. WordPress на Hostinger (shared hosting). Власник — не професійний розробник, навчається веброзробці. Спілкування — українською.

## Архітектура сайту (важливо, щоб не плутатись)

**/vero-page і /vero-page-test** — це ОДНА Й ТА Ж сторінка (WordPress post ID 3914). Контент живе в Gutenberg-блоці, стилі й скрипти — в окремих WPCode-сніпетах ("Vero — Page", "Vero — Styles", "Vero — Scripts", "Vero — Menu", "Vero — Footer" і т.д.). Головний контейнер сторінки — `.vero-app`.

**/book** (post ID 3481) — ОКРЕМА сторінка, побудована на плагіні Fluent Forms, а не на кастомному HTML/CSS/JS. Код форми не лежить у пост-контенті як текст — його не можна витягнути й редагувати як звичайний HTML-файл. Зміни в неї вносяться тільки через WP-адмінку (Edit Page 3481 / налаштування форми Fluent Forms). Структура форми задокументована в `vero-book-STRUCTURE.md`.

Сайт відходить від теми Kadence — не покладайся на Kadence-специфічні компоненти чи класи в нових рішеннях.

## Джерело правди

`MANIFEST.md` — головний документ: структура сторінки, дизайн-система (кольори, типографіка, spacing-токени, zone-паттерн sand/white, стиль кнопок і карток), перелік послуг. Звіряй нові рішення з ним, і онови його, якщо структура сайту зміниться.

Локальні `vero-*-BUILT.html/css/js` файли — відповідники реальних WPCode-сніпетів. Тримай їх синхронізованими з лайвом (не покладайся на пам'ять розмови — реально звіряй, як описано нижче).

## Технічні обмеження середовища (важливо!)

- **curl/wget/Python urllib не працюють** у цьому сандбоксі для звернень до зовнішніх сайтів — мережа блокує. Для отримання реального стану сторінки використовуй браузерні інструменти (navigate + read_page / javascript_tool), не curl.
- **view-source: не підтримується** інструментом браузера.
- **Великий base64 (кілька МБ) і дуже великий HTML можуть підвісити інструменти** (base64-вставка зображень, create_artifact з великим вмістом). Для зображень — заливай через WordPress Media Library вручну (попроси власника, якщо автоматично не виходить), не вбудовуй важкий base64 в код.
- Автоматичне розгортання через Gutenberg іноді проходить частково (структура оновлюється, текст — ні) — після будь-якого деплою ОБОВ'ЯЗКОВО перевіряй вживу, що саме змінилось, а не вір власному звіту про "успіх" без перевірки.
- Модель у Cowork-чаті фіксується після першого повідомлення в розмові й далі не змінюється — обирай модель усвідомлено на старті нового чату.

## Правила безпеки (не порушувати)

- Бекап файлу перед будь-яким редагуванням, у `_backup/[дата]/`, нічого не видаляти.
- Ніколи не змінювати живу базу даних напряму без явного підтвердження власника.
- Перед будь-якою незворотною дією — питати підтвердження.

## Стиль роботи
- Відповідай українською.
- Для коду — вказуй точний шлях до файлу перед блоком коду.
- Після будь-якої зміни на сайті — заходь і перевіряй результат вживу, а не тільки в локальному файлі.
- Якщо не вдалось перевірити щось на 100% (через технічні обмеження вище) — чесно кажи про рівень впевненості, а не видавай припущення за факт.
